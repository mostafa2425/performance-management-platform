# Notification Template Management — Backend Handoff (UC-027)

## Scope from the BRD

UC-027 is an Admin-only procedure for viewing and editing predefined system notification templates. The frontend must not create or delete notification types and must not change recipients, triggers, or workflow conditions.

The Admin may update only:
- English subject
- Arabic subject
- English message body
- Arabic message body

Updated content is used for future notifications generated by the applicable predefined workflow. Previously generated/sent notifications must retain their original content.

## Frontend status

The route `/[locale]/admin/notification-templates` provides:
- A list of predefined templates and their identifiers.
- Read-only recipient, related use case, and trigger/workflow metadata.
- Bilingual subject and body editing.
- Required-field validation before saving.
- Cancel behavior that restores the selected template's initial content.
- An explicit notice that changes affect future notifications only.

The current implementation uses seed data and React page state only. It is not production persistence.

## Backend contract required (to be agreed)

Please confirm the API contract for the following capabilities; this document intentionally does not prescribe endpoint paths or payload shapes.

1. List predefined templates visible to an authorized Admin, including stable template ID/code, display name, related use case, recipients, trigger/workflow metadata, and current bilingual content.
2. Retrieve a template's current content and version.
3. Update only the four permitted content fields.
4. Return field-level validation errors and a concurrency/version conflict if another Admin changed the template.
5. Record audit history with template ID, previous and new values, modified by, and modification timestamp.
6. Ensure notification generation uses the latest saved template content for future events while preserving content already rendered for earlier notifications.
7. Enforce Admin authorization on the server; hiding the route or controls in the frontend is not an authorization boundary.

## Open source-content item

The BRD identifies NOT-017 metadata but does not provide English or Arabic message-body text. Do not seed invented wording. Business owners should provide approved copy before this template can be saved with all required fields.

## Acceptance checks

- Non-Admin users cannot retrieve or update templates.
- Admin can list and view predefined templates.
- Admin can update English and Arabic subjects and bodies.
- Empty required fields are rejected.
- Recipient, trigger, template type, and workflow condition cannot be changed through the update contract.
- Existing/sent notifications remain unchanged after a template edit.
- Future notifications use the updated content.
- Every successful update creates an auditable before/after record.
- Concurrent edits are handled without silently overwriting another Admin's changes.
